# Ретроспектива

Без этого шага библиотека агентов не самосовершенствуется — это главный цикл обучения.

## When to Use
- Системный промпт сообщает о незакрытых ретроспективах.
- После завершения графа задач (финальная задача done).

## Procedure
1. `dlc_retro_pending` — список прогонов без ретроспективы.
2. Для каждого прогона: `kanban_show <task_id>` — исходная постановка, результат, комментарии,
   review, раздел 'Lessons:' из summary исполнителя.
3. Оцени:
   - Выполнен ли DoD? Сколько было rework/review-циклов? Был ли blocked и почему?
   - Была ли задача вообще по компетенции агента (ошибка исполнителя или ошибка планирования)?
   - `dlc_run_record(agent, task_id, outcome, score 0..1, complexity, notes)`.
4. Извлеки уроки — только конкретные и переносимые на будущие задачи:
   - `do`: "При миграции колонок NOT NULL сначала backfill батчами по 10k".
   - `dont`: "Не использовать `any` в публичных типах SDK".
   - `check`: "Перед сдачей прогнать `alembic upgrade head` на пустой БД".
   - `context`: факты о проекте/пользователе, важные для этой специализации.
   `dlc_agent_learn(agent, lesson, kind, source_task=task_id)`.
   Нечего извлечь — закрой: `dlc_retro_pending(close={agent, task_id})`.
5. Ошибка планирования (задача не по профилю) — урок в свой процесс планирования
   (память/скилл оркестратора), а не исполнителю.
6. После уроков: `dlc_agent_evolve(agent)`. Противоречащие/устаревшие уроки — `drop_lesson_ids`.
7. Вывод из ротации: success_rate < 0.4 при ≥ 5 прогонах, или есть агент, стабильно
   лучше на той же компетенции → `dlc_agent_retire(agent, reason, replaced_by)`.
8. Если компетенция исполнителя оказалась шире задачи и это мешало — сузь: forge наследника.

## Pitfalls
- Уроки-банальности ("писать качественный код") — засоряют SOUL. Отбрасывай.
- Обобщение по одному случаю, если причина — внешняя (упал API, не было доступа).
- Не трогай SOUL вручную в обход evolve: потеряется версия.

## Verification
- `dlc_retro_pending` пуст или остались только сознательно отложенные.
