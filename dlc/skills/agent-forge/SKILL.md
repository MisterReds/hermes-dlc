# Создание агента-специалиста

Специалист ценен ровно настолько, насколько его SOUL содержит знание, которого нет у
generalist: методику, типичные ошибки, критерии качества конкретной области.

## When to Use
- `dlc_agent_find` вернул `forge` или `adapt`.
- Повторяющийся класс задач, где generalist ошибается.

## Procedure

### 1. Определи компетенцию
- Одно предложение: "Делает X для Y так, что Z". Если не помещается — это два агента.
- Узость: агент должен уметь отказаться от задачи вне своей зоны.
- `slug` — по компетенции: `pg-zero-downtime-migrations`, `figma-to-react-a11y`,
  `ru-legal-contract-review`. Не `coder-2`.
- `domains` — стек/область/тип артефакта, по ним будет поиск.

### 2. Выбери tier и модель
- `simple` — шаблонная работа, дешёвая быстрая модель.
- `specialist` — основная модель.
- `expert` — редкая компетенция или высокая цена ошибки: сильная модель, обязательный review.

### 3. Напиши SOUL (≥ 200 символов, обычно 1–3 тыс.)
Структура:
```
# <Роль>
Ты — <кто>. Твоя единственная зона: <компетенция>.

## Зона ответственности
- Делаешь: ...
- НЕ делаешь (блокируй задачу с описанием нужной компетенции): ...

## Метод
1. Как ты начинаешь (что читаешь, что проверяешь в первую очередь).
2. Порядок работы, специфичный для области.
3. Как проверяешь результат.

## Стандарты качества
- Конкретные, проверяемые: версии, паттерны, лимиты, стандарты (WCAG AA, RFC ..., PEP ...).

## Типичные ошибки области (анти-паттерны)
- Что generalist делает неправильно и как правильно.

## Definition of Done
- Чек-лист перед kanban_complete.

## Формат сдачи
- Что в summary, какие артефакты прикрепить, раздел 'Lessons:'.
```
Пиши знание области, а не общие слова ("будь внимателен" — мусор).
При `adapt` — возьми SOUL родителя (`dlc_agent_list`) и сузь, добавив специфику.

### 4. Создай
`dlc_agent_forge(slug, title, specialty, soul, domains, tier, model, parent_slug)`.
Профиль получает kanban-тулсет; секция "Lessons learned" в SOUL будет пополняться ретроспективами.

### 5. Навыки агента (опционально)
Если у области есть процедуры/справочники — создай скиллы в профиле агента
(`hermes -p <profile> ...` или `skill_manage` из сессии этого профиля) и упомяни их в SOUL.

## Pitfalls
- Агент-"мастер на все руки" — бесполезен для поиска и не учится.
- Дублирование: сначала `dlc_agent_find`, потом forge.
- SOUL без анти-паттернов и DoD не лучше generalist.

## Verification
- `dlc_agent_find` с исходной потребностью теперь возвращает нового агента с `reuse`.
